## 性能对比与分析

### 1. 加密 vs 解密

| 操作 | 64B (ops/s) | 1KB (ops/s) | 16KB (ops/s) | 解密/加密比 |
|------|------------|------------|-------------|-----------|
| AES-GCM 加密 | 90,909 | 83,333 | 41,667 | - |
| AES-GCM 解密 | 1,000,000 | 333,333 | 111,111 | 11x / 4x / 2.7x |

**关键发现**：
- 解密性能显著优于加密
- 小数据块差异最大（11倍）
- 大数据块差异缩小（2.7倍）

### 2. SHA-256 vs SHA-512

| 算法 | 64B (ops/s) | 1KB (ops/s) | 16KB (ops/s) |
|------|------------|------------|-------------|
| SHA-256 | 1,000,000 | 200,000 | 19,231 |
| SHA-512 | 500,000 | 250,000 | 28,571 |
| SHA-512/SHA-256 | 0.5x | 1.25x | 1.49x |

**关键发现**：
- SHA-256 在小数据块上更快
- SHA-512 在大数据块上更快（64位系统优势）
- 交叉点在 1KB 左右

### 3. 性能瓶颈识别

根据测试结果，识别出以下潜在瓶颈：

1. **随机数生成**：相对较慢（16KB: 15,873 ops/s）
   - 可能瓶颈：熵源获取、系统调用开销
   - 优化方向：批量生成、缓存池

2. **AES-GCM 加密**：小数据块固定开销高
   - 可能瓶颈：初始化开销、上下文切换
   - 优化方向：批量处理、上下文复用

3. **SHA-256 大数据块**：性能下降明显
   - 可能瓶颈：缓存未命中、内存带宽
   - 优化方向：考虑使用 SHA-512（64位系统）

## Phase B 优化实施：随机数生成优化 ✅

**实施日期**: 2026-01-21
**状态**: ✅ 已完成

### 优化目标

根据基准测试结果，随机数生成被识别为性能瓶颈之一：
- 64B: 250,000 ops/s
- 1KB: 111,111 ops/s
- 16KB: 15,873 ops/s

**优化目标**: 实现 2-5 倍性能提升

### 实施方案

实现了**随机数缓存池**（Random Pool）优化：

**核心设计**:
1. **批量生成**: 一次性生成 8KB 随机数据
2. **缓存复用**: 从缓存中快速复制数据
3. **智能重填**: 剩余 < 1KB 时自动重填
4. **大请求绕过**: > 4KB 请求直接生成（避免池开销）

**线程安全**: 使用 `TCriticalSection` 保护共享状态

### 性能测试结果

| 数据块大小 | 启用池 (MB/s) | 直接生成 (MB/s) | 性能提升 | 缓存命中率 |
|-----------|--------------|----------------|---------|-----------|
| **256B** | 221.95 | 32.12 | **6.9x** ⭐ | 100% |
| **1KB** | 207.78 | 84.92 | **2.4x** ✅ | 100% |
| **4KB** | 205.59 | 186.01 | **1.1x** ✅ | 100% |
| **8KB** | 217.01 | 173.61 | **1.0x** | 0% (绕过池) |

### 关键成果

1. ✅ **超额完成目标**: 小数据块性能提升 2.4-6.9 倍
2. ✅ **完整集成**:
   - 核心实现: `src/fafafa.ssl.random.pool.pas`
   - 测试套件: `tests/test_random_pool.pas`
   - Benchmark: `tests/benchmarks/benchmark_random_pool.pas`
   - CI 集成: `scripts/ci_benchmark.sh`
3. ✅ **100% 缓存命中率**: 小于 MaxRequestSize 的请求
4. ✅ **线程安全**: 支持多线程并发访问
5. ✅ **文档完善**: 使用指南、配置说明、最佳实践

### 配置参数

| 参数 | 默认值 | 说明 |
|-----|--------|------|
| `Enabled` | `True` | 是否启用缓存池优化 |
| `PoolSize` | `8192` (8KB) | 缓存池大小 |
| `RefillThreshold` | `1024` (1KB) | 剩余字节 < 此值时重填 |
| `MaxRequestSize` | `4096` (4KB) | 超过此值的请求直接生成 |

### 使用示例

```pascal
uses
  fafafa.ssl.random.pool;

var
  LBuffer: array[0..1023] of Byte;
begin
  // 使用全局池（推荐）
  if PooledRandomBytes(@LBuffer[0], 1024) then
    WriteLn('成功生成随机数据');
end;
```
