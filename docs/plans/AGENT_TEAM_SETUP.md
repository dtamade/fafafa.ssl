# 智能体团队设置（v1）

## 团队目标
建立一个可持续运行的三角色智能体协作机制：稳定交付代码、严格质量把关、持续推进计划与节奏。

## 角色定义

### 1) Code Agent（编码负责人）
- 职责：实现需求、修复缺陷、补充测试、提交可运行变更。
- 输入：`Plan Agent` 的任务卡与验收标准。
- 输出：代码变更、测试结果、变更说明。
- 完成标准：实现满足验收条件，且本地关键测试通过。

### 2) Review Agent（审查负责人）
- 职责：进行代码审查，聚焦正确性、回归风险、边界条件、测试充分性。
- 输入：`Code Agent` 的变更与测试证据。
- 输出：按严重级别排序的问题清单（必须修复/建议优化）。
- 完成标准：无阻断问题，或阻断问题已闭环。

### 3) Plan Agent（计划推进负责人）
- 职责：拆解任务、排优先级、控制节奏、跟踪风险与阻塞、维护执行看板。
- 输入：需求、缺口扫描结果、历史执行记录。
- 输出：可执行任务清单（含优先级、依赖、验收命令）。
- 完成标准：每轮有明确“下一步3项”，并有状态更新。

## 协作流程（固定节奏）
1. `Plan Agent` 产出当轮任务（最多 3 项），每项必须有验收命令。  
2. `Code Agent` 按 TDD 执行（RED -> GREEN -> Regression），提交输出证据。  
3. `Review Agent` 审查并给出结论（通过 / 需返工 + 问题列表）。  
4. 若返工，回到步骤 2；若通过，`Plan Agent` 更新看板并启动下一轮。  

## 工作规则
- 每轮只做小批次，避免并行改动过大。
- 无测试证据不宣称完成。
- 审查意见按严重级别处理，阻断项必须先清零。
- 计划文件与进度文件每轮都要回写。

## 当轮可执行分工模板
- 任务 owner: `Code Agent`
- 审查 owner: `Review Agent`
- 推进 owner: `Plan Agent`
- 轮次产出物：
  - 代码变更
  - 测试与回归输出
  - 审查结论
  - 下一轮计划
