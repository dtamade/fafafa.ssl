# v1.5.0 PR Approval Plan

## Goal

把已经推送到远端的 `release/v1.5.0-prep-2026-05-15` 转成一个可审查、可合并的 GitHub PR，并把 merge approval 与后续 tag/release 明确拆开，避免继续停留在“本地已收口但外部无审批入口”的状态。

## Architecture

- 当前承载分支：`release/v1.5.0-prep-2026-05-15`
- 当前默认基线：`master`
- 当前控制面：`docs/ROADMAP.md` -> `docs/plans/2026-05-12-release-v1.5.0-formalization.md` -> `docs/test_reports/RELEASE_READINESS_V1.5.0.md` -> `.github/README.md`
- 当前 release-prep handoff：`docs/test_reports/RELEASE_PREP_HANDOFF_V1.5.0_2026-05-15.md`
- 本批只允许修改：
  - PR approval 计划文档
  - PR approval packet
  - 根 working-memory 文件
- 本批不允许：
  - 创建 `v1.5.0` tag
  - 发布 GitHub Release
  - 伪装 Windows/WinSSL runtime 证据已补齐
  - 重开新的生产代码实现批次

## Task 1: Draft Approval Assets

Write:

- PR approval plan with scope / commands / stop condition
- approval packet to serve as the single PR body source
- explicit `no-tag / no-release / Windows deferred` boundary
- explanation that readiness wording `READY_FOR_MAIN_MERGE` maps to the repo's actual default mainline branch `master`

## Task 2: Focused Verification

Run from repo root:

```bash
bash tests/scripts/test_release_control_entrypoint_convergence_contract.sh
bash tests/scripts/test_active_roadmap_references_contract.sh
bash tests/scripts/test_release_workflow_v1_5_0_contract.sh
git diff --check
git status --short
```

Expected:

- release-control entrypoint contract remains green
- roadmap truth contract remains green
- release workflow contract remains green
- no whitespace/check drift remains after doc edits

## Task 3: Review, Commit, Push

- summarize a short review conclusion before commit
- commit the PR approval asset batch
- push the updated `release/v1.5.0-prep-2026-05-15` branch to `origin`

## Task 4: Create Or Update PR

If no PR exists:

```bash
gh pr create \
  --base master \
  --head release/v1.5.0-prep-2026-05-15 \
  --title "release: request v1.5.0 merge approval" \
  --body-file docs/test_reports/PR_APPROVAL_PACKET_V1.5.0_2026-05-15.md
```

If a PR already exists:

```bash
gh pr edit <number> \
  --title "release: request v1.5.0 merge approval" \
  --body-file docs/test_reports/PR_APPROVAL_PACKET_V1.5.0_2026-05-15.md
```

Then record:

```bash
gh pr view --json number,title,state,url,mergeStateStatus,reviewDecision,headRefName,baseRefName
```

Expected:

- exactly one PR exists for `release/v1.5.0-prep-2026-05-15`
- base branch is `master`
- PR body comes from the approval packet file

## Task 5: Final Metadata Sync

Update root working-memory with:

- final PR number / title / URL / state
- final branch HEAD after commit + push
- any GitHub-side constraints discovered during PR creation
- explicit statement that merge/tag/release remain outside this batch

## Stop Condition

- `tests/scripts/test_release_control_entrypoint_convergence_contract.sh` 通过
- `tests/scripts/test_active_roadmap_references_contract.sh` 通过
- `tests/scripts/test_release_workflow_v1_5_0_contract.sh` 通过
- `git diff --check` 通过
- PR approval asset commit 已创建并推送
- `gh pr view --json ...` 可返回唯一 PR 元数据
- 根 working-memory 已同步到 PR 审批状态
