# v1.5.0 Release Formalization Plan

## Goal

Prepare `fafafa.ssl` for the stable `v1.5.0` release without opening new feature work. The current default batch is a Linux-side release-control closeout: prove the local release surface, align versioned docs and workflow automation, record the exact state of any Windows/WinSSL follow-up without pretending it was locally verified, and stop before tag creation unless the user gives explicit approval.

## Architecture

This is a release-control batch, not a production-code batch.

- Use the version constants in `src/fafafa.ssl.base.pas` as the source of truth: `1.5.0` and interface version `10500`.
- Keep local release gates release-oriented and repeatable: compile gate, minimal CI gate, FreePascal TLS 1.3 completeness gate, style, and Phase 2 dry-run.
- Convert the old disabled release workflow into an active workflow that uses current gates and `RELEASE_NOTES_V1.5.0.md` instead of an inline old API template.
- Treat Windows/WinSSL runtime proof as an explicit follow-up track, not the default local prerequisite for this Linux-side static closeout. If scope expands beyond the Linux-side release-control lane, record the exact external blocker or runtime gap instead of weakening the release notes.
- Do not create `v1.5.0` until readiness is pass and the user explicitly approves.

## Task 4: Optional Windows Follow-up / Static Workflow Audit

Default path for this plan: keep Windows work static unless a Windows-capable environment is explicitly available and release scope expands beyond the Linux-side closeout.

Static audit:

- keep `test_wave_b_b2_windows_runtime_workflow_contract.sh` green
- keep `test_winssl_windows_validation_bundle_contract.sh` green
- make sure docs/readiness text does not imply Windows runtime proof already exists when it does not

Only if the branch containing the updated workflow is on GitHub and a Windows-capable evidence run is explicitly needed, dispatch:

```bash
gh workflow run .github/workflows/wave-b-b2-manual.yml \
  --ref <pushed-branch> \
  -f run_linux_baseline=true \
  -f strict_closure=true \
  -f run_id=release_1_5_0_20260512
```

Expected artifacts if that follow-up is actually run:

- `wave-b-linux-release_1_5_0_20260512`
- `wave-b-macos-release_1_5_0_20260512`
- `wave-b-windows-release_1_5_0_20260512`
- final cross-platform summary artifact

Windows artifact must include:

- quick smoke log
- Wave B Windows gate summary and step logs
- broader WinSSL runtime suite transcript

Failure handling:

- environment failure: record tooling/runner dependency and do not open production code
- entrypoint failure: fix workflow/script path drift, then rerun the focused contract
- implementation failure: only then open a `src/fafafa.ssl.winssl.*` repair batch
